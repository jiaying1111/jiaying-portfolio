# Portfolio Browser QA — 2026-08-26

Audited locally at `http://localhost:3000` against the exported Figma references
in `docs/figma-reference/export-2026-08-26/`.

> Current-copy notice: `docs/content.md` was retranscribed from the newest ZIP
> exports after this QA pass. It overrides every wording example or suggested

## Overall result

The site has a usable responsive skeleton, but it is not yet a faithful Figma
implementation. The main defects are missing Homepage hero content, placeholder
copy and incorrect metadata throughout Experience and Artwork, an incomplete
About page, and provisional project-detail pages. These are content and visual
fidelity failures rather than isolated polish issues.

## Source-of-truth rule

For desktop visual decisions, use these files as the authority:

- Homepage: `home-intro.png`, `home-digital-no-more-mad.png`,
  `home-dreamwhorl.png`, `home-little-red-riding-hood.png`, `home-nushu.png`
- Experience: `experience-projects.png`, `experience-practice.png`
- Artwork: `artwork-installation.png`, `artwork-illustration.png`
- About: `about-layout.jpg` plus `about-content-reference.png`
- Dimensions/tokens: `docs/design-system.md`
- Asset paths/order: `docs/media-library.md`

Never render a complete reference export as a page background. Reconstruct the
layout with semantic HTML/React and the individual assets in `public/`.

## P0 — blocks visual approval

### Homepage

1. The visible hero introduction is missing. The current first slide shows the
   background image but not the Figma greeting, name, tagline, or social links.
   The only H1 is visually hidden.
2. The desktop header uses white text over the hero and is nearly invisible.
   The Figma Homepage header/logo/navigation are dark and must match the
   reference positions and typography.
3. Carousel controls do not match Figma. The current UI shows a previous arrow,
   five dots, and a next arrow. The Figma states use the specific circular
   social/next controls shown in each reference, with a single next action on
   project slides.
4. The carousel did not advance during a 5.6-second observation. Implement and
   verify autoplay, pausing, focus behavior, page-visibility behavior, and
   reduced motion rather than merely rendering all five slides.
5. All five slide images currently remain `opacity: 1`; only stacking order
   distinguishes the active slide. Inactive slides must be visually and
   interactively inactive (`opacity: 0`, `visibility`, `pointer-events`, and
   correct `aria-hidden`).
6. At 390px viewport width, `.hero-carousel` has a computed height of `0px`.
   The entire mobile hero disappears and the page begins with Experience
   Design. The hero must remain present and legible on small screens.

### Experience Design

1. Every listing summary is placeholder copy beginning with
   `This project etc is a uiux design...`.
2. DreamWhorl is incorrectly displayed as `DreamScope`.
3. Project metadata is mostly the same incorrect `UIUX / 2025 / Figma` data.
   Replace it with the exact reference content below.
4. The two tab layouts are geometrically close to Figma, but the wrong text
   makes the page visibly unfinished.

### Artwork

1. The page intro incorrectly repeats the Experience Design sentence. Figma
   says: `Through installations and illustrations, I create playful worlds
   where objects, images, and stories invite new ways of seeing.`
2. All nine listings use placeholder summaries and the same incorrect
   `UIUX / 2025 / Figma` metadata.
3. Every `View Project` control is a disabled button with
   `aria-disabled="true"`. It looks interactive but cannot be activated. Use a
   real link when a destination exists; otherwise do not present a disabled
   control as a completed feature.
4. Illustration is 4,822px tall at 1440px, while the Figma reference is about
   4,646px. Row spacing/rhythm is too loose and must be tuned against the
   reference after the copy is corrected.

### About

1. The page is not a faithful reconstruction of `about-layout.jpg`. Its
   desktop height is about 4,163px versus roughly 6,091px in the reference;
   the intended whitespace, row rhythm, rules, and hierarchy are compressed.
2. Education is incorrect. Use Harvard University — Expected 2028 — MDes
   Mediums; Rhode Island School of Design — June 2026 — Illustration (Honor
   Distinction).
3. Experience is incorrect and contains invented roles/bullets. The reference
   identifies Shanghai Concord Bilingual School — Teaching Assistant — July
   2026; RISD — Teaching Assistant — Sept 2025–Dec 2025; Lenovo — Visual Design
   Intern — June 2025–Aug 2025. Use only approved supporting copy.
4. A redundant `Introduction` heading appears in the structure although the
   Figma composition begins with `About`.
5. The portrait produces an aspect-ratio warning because CSS changes only one
   dimension. Preserve its intrinsic ratio (`width: auto`/`height: auto` or an
   explicit matching aspect ratio).
6. Skills contain `Finalcut` and `Java Script` in the current reference. Do not
   silently normalize visible copy; follow `docs/content.md` until the designer
   approves a wording change.
7. Social URLs are still generic `instagram.com` and `linkedin.com` values,
   not verified personal destinations.

## P1 — fidelity and interaction corrections

### Homepage Experience cards

- The first hover title says `Digital Nomad`; it must be
  `Digital No More Mad`.
- The hover crossfade is muddy/slow: after 800ms the hover layer was still only
  about 41% opaque. Use a restrained 250–400ms transition that cleanly reaches
  opacity 1 while keeping a stable hit target.
- Retain a semantic title outside/running alongside any text rasterized into an
  SVG. Touch users must not depend on hover.

### Homepage Artwork rail

- Continuous motion exists and the DOM correctly duplicates the rendered
  eight-item track, but the visible starting sequence/crops do not align with
  the Figma Homepage reference. Use the exact asset order in
  `docs/media-library.md` and set the initial translation so the 1440px crop
  matches `home-intro.png`.
- Preserve the 350px tile size and 14px gap at the reference viewport; pause on
  hover/focus and disable animation for reduced motion.

### Shared performance/accessibility

- The first Re:Sounding Nature and Circular Ruins images trigger Next.js LCP
  warnings. Mark the first above-the-fold image on each artwork tab as eager or
  priority; keep lower images lazy.
- Give the mobile `Menu` button an explicit accessible name/state and verify
  keyboard navigation, focus visibility, and menu dismissal.
- Ensure controls that change tabs expose selected state and remain reflected
  in the query string.

## Confirmed working — preserve these behaviors

- Experience and Artwork hover media use a stable 623×420 wrapper and cycle
  through all three frames without layout shift.
- All Illustration images load successfully after they enter the viewport;
  the gray lower-page state observed before scrolling is normal lazy loading,
  not missing files.
- No horizontal overflow was detected at 390px on the audited routes.
- The Homepage Artwork rail contains one rail with two copies of the eight-item
  track for a seamless loop. Do not misdiagnose full-page screenshot stitching
  artifacts as duplicated React sections.
- Tabs and primary route links work, and Experience project links reach their
  detail routes.
